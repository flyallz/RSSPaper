# 代码架构与维护说明

Windows 与 macOS 的当前版本共用 `src/journal_radar/`。两端旧路径
`src/universal/v1.1/` 和 `src/universal/macos-v1.1/` 只保留启动兼容入口、
历史说明和各自的打包规格。不要在旧入口中实现业务。

## 模块职责和依赖方向

```text
app.py                       启动与诊断入口
ui/                          页面、论文卡片、Qt 后台任务
  main_window.py             动作转发、任务生命周期
  main_view.py               主页面布局和用户操作信号
  source_editor.py           单个来源输入和校验反馈
  sources_dialog.py          来源管理页面
  settings_dialog.py         应用设置页面
  paper_card.py              单篇论文展示，通过信号请求翻译
  workers.py                 将 Qt 信号连接到业务任务
services/                    不依赖 Qt 的应用业务
  workspaces.py              学科、来源、设置的事务式编辑
  refresh.py                 并发刷新和缓存合并规则
  papers.py                  页面筛选条件
  translations.py            请求配置快照和译文缓存键
  abstracts.py               按需摘要补全、学科隔离和缓存保留
adapters/                    外部格式及服务接入
  rss.py / crossref.py        解析数据，不发网络请求
  source_registry.py         来源注册、地址构造和统一获取
  http.py                    TLS、超时、响应大小和重试
  translation.py             大模型翻译接口
  abstracts.py               Crossref DOI/唯一标题查询和摘要清理
  subscriptions.py           OPML 和历史 JSON 文件
domain/                      数据契约、默认值、校验和纯规则
storage.py                   配置读取、原子写入、损坏配置保护
platform/                    平台差异
  paths.py                   数据目录、字体、提示文字
  secrets.py                 按操作系统选择密钥后端
  macos_keychain.py           原生 SecItem 钥匙串接口
  windows_dpapi.py            当前 Windows 用户的 DPAPI 加密
```

依赖方向为：界面调用业务；业务组合接入、存储和平台能力；接入依赖领域模型。
领域层不能导入 Qt、网络请求、存储或平台接口。后台任务不能操作控件。
`tests/test_architecture.py` 对这些基本边界进行检查。

`core.py` 只用于旧诊断脚本的兼容导出。新增生产代码应直接导入职责模块，
不能把新逻辑重新堆进 `core.py` 或旧版入口。

## 数据和兼容性

`domain/models.py` 使用 TypedDict 定义来源、论文、学科、设置和状态。
数据仍是 JSON 兼容结构，保留 schema 1、已有 ID、数据目录和译文缓存键，
不需要用户重新导入订阅。配置读取边界由 `validate_state()` 校验并补齐旧字段，
保留未知扩展字段；不支持的版本或损坏结构明确报错。

`StateRepository` 捕获同一会话的读取失败状态，禁止把空白回退工作区写回损坏的
原文件。用户应先备份并修复配置，再重启。正常保存通过同目录临时文件与原子替换
完成；工作区编辑先保存候选状态，成功后才修改界面共用的状态。

Mac 仍使用原来的 service/account，改为直接调用 Security.framework，
避免通过命令行参数传递密钥。Windows 仍使用 DPAPI。密钥不进入 state.json，
单元测试不读写用户已保存的真实密钥。

## 新增会议或期刊来源

1. 先确定可靠入口及其更新语义。会议卷、单篇论文、预印本要明确区分。
2. 在 `adapters/` 编写解析器，将数据转换为统一的 Paper。
3. 在 `source_registry.py` 注册 SourceAdapter，提供地址构造和解析函数。
4. 在 `domain/models.py` 扩展来源类型，在 `domain/sources.py` 增加入参校验。
5. 在来源编辑页面加入类型和提示；来源管理页面增加名称标签。
6. 添加脱敏的样本回归测试，覆盖缺少摘要、日期精度、空结果及失败情况。

通用刷新、筛选、缓存合并和论文卡片无需随每个来源修改。
AIED、AAAI 等来源的具体接入方案仍须根据官方数据源单独实现。

## 修改翻译或缓存

翻译适配器负责构造请求和解析响应；TranslationJob 负责请求快照与缓存标识。
发起任务时固定接口、模型、文本、目标语言和内容类型；结果按这份快照缓存，
不能读取“请求结束时”的设置生成缓存键。
如果设置已经更改，旧请求结果可以保存，但不能显示成当前模型的译文。

来源失败时保留其已有论文；成功但经过筛选后为空时清空该来源旧结果。
刷新结果归属发起任务的学科，不能归属当时界面新选中的学科。

## 日常开发

```sh
python -m venv .venv
python -m pip install -r requirements-build.txt
PYTHONPATH=src python -m journal_radar
python -m ruff check .
python -m ruff format --check .
PYTHONPATH=src QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v
python scripts/build-universal.py
```

Windows PowerShell 设置环境变量时使用：

```powershell
$env:PYTHONPATH = "src"
$env:QT_QPA_PLATFORM = "offscreen"
python -m unittest discover -s tests -v
```

测试结果中的“跳过 Windows DPAPI”或“跳过 macOS 框架”是平台限定测试；
对应测试应在各自的 CI 机器上执行。代码格式与导入顺序由 Ruff 固定。
测试以业务行为为主，不依赖实时出版社服务或收费 API。

## 构建与发布

唯一版本来源是 `journal_radar/config.py` 中的 VERSION。Python 包版本、
Mac bundle 版本和打包文件名都读取它。依赖由根目录 requirements-build.txt
统一固定，平台专属构建依赖使用环境标记。该文件是版本清单，不是带哈希的供应链锁文件。

CI 在 macOS 和 Windows 上使用同一套测试，随后打包并运行冻结程序自检和界面
启动检查。产物和 SHA-256 写入 `dist/artifacts/`；新增安装包不要提交到 Git。
历史安装包暂时保留，后续迁移需单独处理下载链接和仓库历史。

发布流程手动触发，默认仅生成构建产物；选择创建发布时，两端成功后生成草稿。
正式发布前仍需人工检查兼容性、版本说明、Windows 签名及 Mac Developer ID
签名/公证。当前构建不会声称安装包已正式签名。

CI 的 macos-15 与 Windows runner 标签按 [GitHub 官方运行器说明](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) 配置。
