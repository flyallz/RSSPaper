# 摘要补全与机构访问（v1.4.1）

## 用户操作

论文卡片区分无摘要、出版信息、摘要片段、完整性未确认的来源描述和来源提交的完整摘要。
RSS 没有省略号并不能证明摘要完整，旧缓存也会按这个规则重新识别。
“获取完整摘要”通过 DOI 查询 Crossref；没有 DOI 时先检索标题，只有标题规范化后
一致且候选 DOI 唯一才继续。无法匹配或出版社没有提交摘要时保留原内容并显示原因。
这不是 AI 生成摘要，也不会通过网页爬取、浏览器 Cookie 或学校密码获取内容。

获取成功后摘要标明 Crossref 来源和获取日期，超过 360 字符可展开或收起。
“摘要译为中文/英文”仍由用户单独点击；译文按实际摘要文本、模型、接口和语言缓存。
摘要发生变化后，旧片段的译文不会显示成新摘要的译文。翻译时实际摘要会发送到用户配置的接口。
补全摘要保存在用户本机，正常刷新和重启后保留；不同学科的结果不会串写。
同时最多进行三个摘要查询，查询失败可重试，现有论文仍然可读。

## 校园网验证尚未完成的部分

校园网不会改变 RSS 字段或 Crossref 的公开记录。ScienceDirect 的机构访问需要
API Key 与学校授权 IP/机构令牌及对应接口权限；浏览器 WebVPN 登录不能直接视为
桌面应用已授权。目前没有实际机构网络和凭据，不能声称已完成校园网补全。

后续应在用户本人环境中测试：

1. 普通网络与学校认可的校园/VPN 出口，先确认同一篇论文的浏览器访问权限。
2. 使用本人的 Elsevier API Key 检查同一 DOI/PII 的 API 权限和摘要返回。
3. WebVPN/单点登录单独验证，不读取或上传学校密码、浏览器 Cookie。
4. 知网先确认学校提供的机器访问接口或包含摘要的题录导出方式，再决定适配。
5. 校外退出认证后再次测试，区分公开摘要、机构授权摘要和已有本机缓存。

## 维护边界

- `domain/papers.py`：摘要状态识别、DOI 规范化；不依赖网络或 Qt。
- `adapters/abstracts.py`：Crossref 查找、严格匹配、结构化摘要转纯文本。
- `services/abstracts.py`：不可变任务快照，按学科/论文身份应用结果，刷新时保留补全缓存。
- `ui/workers.py`：后台执行；`paper_card.py` 发出补全信号；主窗口管理任务生命周期。

未来出版社 API 另建适配器，业务服务组合各途径；不要在卡片或 RSS 解析器中加入
登录、抓网页或机构认证逻辑。schema 1 兼容保留，仅增加可选论文字段。
